## 1. Goal

InfinityVolume is a members-only financial intelligence platform with two halves:

- **Data layer** — daily price, volume, market cap and turnover across 15 markets, all normalised to USD, plus ETFs, commodities, FX, treasury yields, credit spreads, housing and macro indicators.
- **Community layer** — member-authored research articles with a peer review pipeline, public/private channels, direct messaging, contacts, bookmarks, watchlists/report generator, and a human-powered research desk ("Human Intel"). This half is the differentiator and where most recent work has gone.

Positioning: an "AP wire for markets" plus a curated community of verified human investors. No AI-generated research; Human Intel is explicitly human-answered.

Brand: display as **Infinity**; legal and operational name **InfinityVolume**. Legal entity named in docs: **Infinity Group LLC** (New Hampshire chosen over Delaware; actual filing status unconfirmed).

Phase 1 target was 20 September 2026, so treat Phase 1 as at its deadline.

## 4. Roles, permissions and reputation

**Admin roles** — stored in `profiles.admin_role`, FK to the editable `admin_role_definitions` table. SA can edit labels, colours, descriptions and permissions, and create new roles without a code change.

- **SA** `super_admin` — everything, including creating public channels, pinning articles to the homepage Discussion box, assigning roles
- **RA** `research` — article review queue (approve / request changes / reject), Human Intel queue
- **TA** `technical` — support ticket queue, flagged content queue
- **CA** `community` — hide/lock public channel posts, Human Intel queue, grant +5 Omega boost (max 3 active per CA, max 1 per member)

**Member tiers** driven by Omega score: Member (0–39), Captain (40–69), Quarterback (70–89), Senior Research Analyst (90+). Plus an unused `is_og_member` badge field. Thresholds are deliberately provisional and will be recalibrated once real usage data exists.

**Omega score** is a weighted composite — article quality 25%, channel posts 20%, likes received 20%, article reactions 15%, network/contacts 10% — plus any CA boost. Recomputed by DB triggers on posts, likes and contacts.

## 5. What is built and working

### Market data / public site
- Homepage: ticker tape, US equity table with sortable columns and 1D/3D/7D/15D/custom date range, Treasury yields card, ETF card, Corporate Bonds & Home Sales card (now IG/HY OAS credit spread tiles), Broad Financial Conditions card, News Flash, Discussion box
- Landing pages: `/treasury`, `/etfs`, `/financial-conditions`, `/market-activity`, `/markets/[market]`, `/markets/[market]/[ticker]`, `/etf/[symbol]`, `/indicator/[key]`
- `/commodities-fx` combined page with collapsible subsections (Precious Metals → Crypto → Energy → Global Consumption) plus an FX section. `/commodities` redirects here. `/cosmos` is a placeholder whose content is still undefined
- Search index (188 items) for stocks, ETFs, treasuries and indicators, with autocomplete in the header

### Auth
- Google OAuth + email/password sign-up, email confirmation enabled, forgot/reset password
- **2FA phone verification for new accounts only** — `/verify-phone`, `/api/phone-otp/send`, `/api/phone-otp/verify`. Six-digit OTP, 10-minute expiry, SHA-256 hashed with `OTP_SECRET`, 3 sends per hour, 5 attempts per OTP, max 2 accounts per number (US and international), SA override via `phone_exception`. The 5 legacy accounts are grandfathered via `requires_phone_verify = false`

### Community
- Public and private channels; public channel creation is SA-only, reachable via the sidebar "Public Channels" header
- Discussion posts with threaded replies (one level deep), likes, bookmarks, flags, pinning, CA hide/lock
- Article publishing: TipTap editor with autosave, featured image, tags, reading time, position-disclosure and own-critique free-text fields, collaborator management, market-update template
- Article submission to channels — public channels go to the RA review queue, private channels publish immediately
- RA/SA review queue with comments, quoted text, author responses, and approve / request changes / reject. Author sees a red "changes requested" banner with comments plus a response box and a "Publish Again" button. "Recall to drafts" available while pending
- Channel article sub-pages at `/member/channels/[channelId]/articles/[articleId]` with breadcrumbs, author bio card, comments, likes
- SA can pin up to 10 articles to the homepage Discussion box — draft state plus an explicit Save, writing through `/api/homepage-save` with the service role
- Contacts and DMs — contact requests flow through the unified `pending_requests` system, mutual acceptance required before messaging, messaging permission toggles in Settings, compressed composer, file attachments (images 5MB; PDF/Excel/Word/PPT 25MB; CSV/JSON/TXT/MD 10MB; video, audio, executables, archives and SVG blocked)
- Human Intel — member submits a question plus context, one active request enforced by a partial unique index, CA/RA/SA queue with Accept & claim / Respond / Ask follow-up / Deny, yellow sidebar dot that clears on visit
- Report Generator (formerly Watchlists) — custom columns (max 6), sorting, CSV export, PNG image export via `next/og`, custom report title
- Support & Feedback, now "Tickets & Requests" — bug / feature / data issue / dataset request with community upvoting, TA queue with status and internal notes
- Content search in three contextual places: private channels page, Human Intel right panel (public channels), Contacts page (DMs). All search title + body + tags + post content
- Sidebar — 48px hover-expand icon strip on the homepage and `/markets/*`, permanent sticky sidebar elsewhere, collapsible sections, pinned channels, user panel with avatar/status/profile modal, Ω score in the header account button

### Email (Resend, live and confirmed delivering)
Eleven trigger types: role assigned / changed / removed, Human Intel answered / follow-up / denied, article approved / changes requested / rejected, private channel invite. Plus a 48-hour author engagement digest on cron `0 18 */2 * *`. All fire-and-forget through `/api/email-trigger`.

### Legal / compliance
`/terms` and `/privacy` live, with SMS sections added for Twilio A2P — the exact required phrases are present ("message and data rates may apply" and the no-sale-of-SMS-opt-in-data statement). `/sms-optin-demo` is a public read-only mock of the opt-in journey, submitted to Twilio as opt-in proof. Liability cap $100; governing law New Hampshire.

## 6. Decisions already made — do not relitigate without reason

- **No downvotes.** Flag/report routed to admin review instead, because downvotes punish contrarian financial analysis
- **No algorithmic feed.** Chronological plus an optional "Hot" sort (log-scaled likes with time decay)
- **Private channels bypass RA review**; public channels always require it
- **Unread/read tracking deferred to Phase 2**, along with per-channel mute, notification granularity, presence status, digest preferences
- **Monetisation: freemium.** Free tier gets limited utilities, no private channels, limited depth behind homepage charts. Paid gets full depth. The existing "compact homepage card → detailed landing page" split maps naturally onto the paywall boundary. Stripe not integrated; tier-by-tier feature map not written
- **Corporate bond breadth replaced by IG/HY OAS spreads** rather than paying FINRA $1,650/mo
- Commodities subsection order: Precious Metals → Crypto → Energy → Global Consumption, with gold and bitcoin as the first rows of their respective sections rather than a separate featured strip
- Spread tiles show the absolute bps figure first on the left, no arrow inside the tile, then 1D and 1W changes without +/- signs since colour carries direction
- Phone limit: 2 accounts per number for both US and international, with SA exceptions

## 7. Constraints worth knowing

- **The assistant sandbox has no network access** to Yahoo, FINRA, Redfin, FRED or Supabase directly. Only PyPI, npm, GitHub and api.anthropic.com. All API testing must be run locally or read through the browser tool.
- **Files cannot be written to the local machine.** Every change must be delivered as a downloadable file plus an explicit "place at this path" table. This is the single largest source of lost time in the project — many "same error persists" cycles were simply a file that had not been placed.
- Browser automation is available via Claude in Chrome, but tabs must be in the assistant's tab group, and typing into React-controlled inputs often does not fire `onChange` (use `document.execCommand('insertText')` or click-then-type).

## 8. Recurring failure modes and their fixes

These cost many hours. Check them first when something breaks.

| Symptom | Cause | Fix |
|---|---|---|
| `42P17 infinite recursion detected in policy` | Two RLS policies referencing each other's tables | Wrap the lookup in a `SECURITY DEFINER STABLE` function (`is_article_collaborator`, `is_channel_member`, `is_channel_admin`, `is_ra_or_sa`) |
| `Could not find the table 'public.x' in the schema cache` | PostgREST schema cache stale | `notify pgrst, 'reload schema';` or drop and recreate the table in a clean SQL tab |
| SQL reports "Success" but nothing changed | **The Supabase SQL editor appends new statements to whatever is already in the tab.** This silently re-ran old statements and masked results many times | Always open a genuinely new query tab before running DDL |
| Vercel build `Module not found` for a file that exists | macOS is case-insensitive; git did not track the case rename | `git rm --cached <file>` then re-add, or a two-step `git mv` |
| Local changes not appearing | Turbopack stale cache | `rm -rf .next && npm run dev` |
| `git push` rejected, non-fast-forward | The data pipeline pushed JSON while you were working | `git checkout -- web/public/data/`, then `git pull`, then commit your code file |
| Env var change has no effect | `NEXT_PUBLIC_*` is baked in at build time | Redeploy, and if needed redeploy without build cache |
| Insert silently fails with no error | RLS blocking, or `.update()` matching 0 rows | Log the Supabase `error` object explicitly; never destructure only `data` |
| `PGRST201 more than one relationship found` | A new table added a second FK path to `profiles` | Disambiguate the embed: `profiles!articles_user_id_fkey(...)` |
| Storage upload `Invalid key` | Raw filename with spaces or colons in the object path | Never use the original filename; use `uuid + sanitized extension` |
